# Frozen rounds and recovery

Call `prepare_run` with a validated request, exact roster and observed capabilities. The JSON envelope holds the existing C02 reducer unchanged plus lossless public contexts, immutable-by-hash round snapshots, actual persona records and frozen evidence/version labels. Persona bundle label and each persona's actual revision are distinct; input hash includes persona contents. Caller facts include original question, source, workflow hard constraints, provided references and permission limits.

`next_actions` is repeatable and has no side effects. Submit an exact intent through `step`, then invoke the real tool. Physical thread IDs are separate from logical actor IDs. Slots count queued creations and every unclosed thread, including idle threads. Completed batches require registered close intents and confirmed cleanup events. No close confirmation means no reclaimed slot.

`advance_round` requires complete prior actor coverage, no pending actions, confirmed cleanup, sufficient total turns and a target claim or new-evidence task. Every actor uses the same stored snapshot, which contains strictly earlier rounds. Own original claims, limitations, revisions, source references and seen evidence IDs are retained verbatim; no lossy compressor exists. `restore_actor` rejects incomplete or omitted histories. This restores public protocol history only, never hidden model state.

Structure repairs use the same total budget, at most once per actor/result. Refusal, uncertainty and disagreement are not repair reasons. Wait timeouts leave tasks pending. Host-reported cumulative elapsed time triggers a terminal partial result at the soft deadline; it cannot kill a background task. Dispatch uncertainty halts new creation until reconciled with an actual receipt. Cancellation immediately stops new work but returns close proposals and retains residual IDs until confirmed.

Terminal states never resume. `resume_run` checks input/protocol/persona/evidence versions and remaining budget, rejects unknown dispatch, and validates frozen snapshot hashes. Changed input needs a new run explicitly linked with parent_run_id; old evidence must be revalidated. Without separately approved persistence, recovery is in-memory only. JSON envelope callers must retain authentic state; the helper is not a signed journal or a trust boundary against a caller who rewrites the entire state.
